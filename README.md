# massmap

Сборка заключения о перспективах пополнения конкурсной массы: поиск транзитных цепочек в платежах, квалификация находок по составам оспаривания, готовый документ на выходе.

Это связующий слой. Скоринг контрагентов (`fns-debt-risk`) и поиск практики (`hybrid-search-ru`) живут в своих репозиториях и подключаются через адаптеры; без них пайплайн работает, просто мельче.

## Что делает

```
платежи (CSV) ──> граф ──> удаление объяснённых рёбер ──> компоненты
                                                              │
             скоринг ФНС ──┐                                  ▼
                           ├──> квалификация по 61.2 / 61.3 ──> заключение
             поиск практики ┘
```

Компонента сильной связности в графе платежей — множество лиц, между которыми деньги могут вернуться к отправителю. Алгоритм находит их за один проход, независимо от длины цепочки и числа участников. Это и есть та работа, которая вручную занимает недели чтения выписок.

## Запуск

```bash
pip install -e ".[dev]"

massmap \
  --payments data/payments.csv \
  --entities data/entities.csv \
  --debtor-inn 7701000001 \
  --debtor-name "ООО «Должник»" \
  --accepted 2025-01-20 \
  --claim 18000000 \
  --out zaklyuchenie.md
```

Пример входных данных и результата — в `examples/`.

### Формат платежей

`payer,payee,amount,when,purpose,doc` — ИНН плательщика, ИНН получателя, сумма, дата (ГГГГ-ММ-ДД), назначение, реквизит документа.

### Формат участников

`inn,name,affiliated,affiliation_source` — ИНН, наименование, признак аффилированности, источник вывода об аффилированности.

## Ключевое решение: отсев до поиска, а не после

Наивное правило «в компоненте встретилось безобидное назначение платежа — исключаем компоненту» разваливается на первом реальном примере. Один встречный платёж по аренде склеивает арендодателя с транзитной цепочкой в одну компоненту, после чего наивный отсев вычёркивает всю цепочку вместе с ним.

Поэтому порядок обратный: сначала из графа удаляются рёбра, которым есть хозяйственное объяснение, и только потом ищется связность. Объяснённый платёж не должен создавать связность, на которой строится вывод о транзите.

Компонента, распавшаяся после отсева, попадает в заключение отдельным разделом с указанием причины. Раздел об исключённых компонентах важнее раздела о находках: он показывает, что работа велась на отсев версий, а не на набор страшных цифр. Регрессионный тест на это поведение — `test_explained_edge_does_not_absorb_transit_chain`.

## Периоды подозрительности

Границы сверены по тексту Федерального закона от 26.10.2002 № 127-ФЗ в редакции, действующей на 01.09.2026:

| Норма | Период |
|---|---|
| п. 2 ст. 61.3 | один месяц до принятия заявления |
| п. 3 ст. 61.3 | шесть месяцев |
| п. 1 ст. 61.2 | один год |
| п. 2 ст. 61.2 | три года |

Все четыре охватывают и сделки, совершённые после принятия заявления.

**Требует пересмотра к 27.07.2027.** Федеральным законом от 26.07.2026 № 253-ФЗ в статьи 61.2 и 61.3 внесены изменения, вступающие в силу с этой даты. Отдельно учитывается Постановление Конституционного Суда от 03.02.2022 № 5-П о признании пункта 1 статьи 61.2 в части не соответствующим Конституции.

Календарная арифметика — по месяцам, а не по тридцать дней: от 31 марта минус месяц даёт 28 февраля, и это покрыто тестом.

## Подключение внешних модулей

```python
from massmap.pipeline import run

class FnsScorer:                       # обёртка над fns-debt-risk
    def score(self, inn): ...          # -> (уровень, [факторы])

class HybridSearch:                    # обёртка над hybrid-search-ru
    def find(self, query, k=5): ...    # -> [реквизиты актов]

report = run(case, payments, entities, scorer=FnsScorer(), search=HybridSearch())
```

Практика, найденная поиском, — кандидат, а не ссылка. В процессуальный документ она попадает только после сверки реквизитов по первоисточнику; в заключении об этом стоит прямая оговорка.

## Границы применимости

Компонента сильной связности означает возможность возврата средств к отправителю, а не доказанность транзита: за циклом может стоять обычный взаиморасчёт. Инструмент сужает поле проверки и не заменяет её.

Полнота результата определяется полнотой выгрузки. Платежи через счета вне периметра в граф не попадают, поэтому без банковских выписок заключение показывает связи, но не движение средств.

Заключение не является экспертизой в процессуальном смысле.
